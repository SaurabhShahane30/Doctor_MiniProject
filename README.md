# Doctor–Patient Healthcare Portal

A full-stack healthcare portal prototype that connects patients and doctors. Patients can discover and connect with doctors, review prescriptions, and analyze medical-report PDFs. Doctors can view connected patients, record clinical details, and create prescriptions with generated PDFs.

> **Project status:** This is a learning/demo project, not a clinical system. Do not use it with real patient information or for medical decisions. Authentication and data-access controls need a security review before deployment.

## What it does

- **Patient and doctor accounts:** Separate sign-up and sign-in flows; passwords are hashed and sign-in issues a JWT.
- **Patient–doctor connections:** Patients can add or remove doctors, and doctors can view their connected patients.
- **Prescriptions:** Doctors can enter symptoms, diagnosis, medications, and notes. The backend saves the prescription to MongoDB and generates a PDF.
- **Medical reports:** Patients can upload a report PDF in the browser. The app extracts text, requests an AI-generated summary, key findings, and recommendations from Groq, and saves the result.
- **Dashboards:** Patients can view prescriptions and saved report summaries; doctors can search their patient list and open patient reports.

The prescription page also includes an audio-recording interface, but its current “generate” action uses mock data and is not connected to a speech-to-text or AI service.

## Tech stack

| Area | Technologies |
| --- | --- |
| Frontend | React 19, Vite, React Router, Axios, Tailwind CSS |
| Backend | Node.js, Express 5 |
| Database | MongoDB with Mongoose |
| Authentication | JSON Web Tokens and bcrypt |
| Documents | PDF.js for browser-side PDF text extraction; PDFKit and Multer for prescription PDFs and uploads |
| AI integration | Groq chat completions API for report summaries |

## How the application is organized

```text
backend/
  controllers/     Request handling and business logic
  models/          Mongoose schemas for users, patients, reports, prescriptions
  routes/          Express API routes
  uploads/         Generated and uploaded PDF files
  server.js        Express app, MongoDB connection, and API mounting
frontend/
  src/
    doctorComponents/
    patientComponents/
    App.jsx         Client-side routes
```

The React app communicates with the Express API on `http://localhost:5000`. MongoDB stores account data, patient reports, and prescriptions. Prescription PDFs are generated by the backend and served from `/uploads`.

## Run locally

### Requirements

- Node.js and npm
- A MongoDB connection string (local MongoDB or a hosted deployment)
- A Groq API key if you want to use report analysis

### 1. Configure and start the backend

Create `backend/.env` with:

```env
MONGO_URI=your_mongodb_connection_string
JWT_SECRET=replace_with_a_long_random_secret
```

Keep environment files and API credentials out of source control. The server currently listens on port `5000`.

In a terminal:

```bash
cd backend
npm install
npm start
```

### 2. Start the frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite (usually `http://localhost:5173`).

## API overview

The backend mounts these route groups:

| Prefix | Examples |
| --- | --- |
| `/api/user` | Doctor sign-up/sign-in, profile, and doctor listing |
| `/api/patient` | Patient sign-up/sign-in, profile, doctor connections, and doctor patient list |
| `/api/reports` | Create reports and retrieve a patient's reports |
| `/api/prescriptions` | Create and retrieve prescriptions; upload a PDF |
| `/uploads` | Serve uploaded and generated files |

## Implementation notes and limitations

- The frontend currently uses a fixed local API address (`http://localhost:5000`); configure an API base URL before deploying it elsewhere.
- The report analyzer sends extracted report text to Groq. Medical documents may contain highly sensitive information; the current client-side integration and credential handling are not suitable for production.
- A Groq credential is currently present in frontend source, and `backend/.env` is tracked by Git. Revoke/rotate exposed credentials, remove secrets from the repository and its history, and move provider calls server-side before publishing.
- Authentication middleware is applied to some routes, but authorization coverage is incomplete. Review every endpoint and enforce patient/doctor ownership before deployment.
- The backend package does not currently define an automated test suite.

## Privacy and security

This project handles health-related data and calls an external AI provider for report analysis. Use synthetic data for demos. Before publishing or deploying, remove and rotate any credentials already committed to the repository, keep new credentials server-side, exclude `.env` files from Git, and complete a security and privacy review.
